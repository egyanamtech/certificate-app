🎓 Certificate & Results Management System
Official Records Office · Tamper-proof certificates · semester-wise results · public verification · role-based admin portal
About · Features · Policies

1 · About the Application

The university runs a secure certificate platform combining a public website (verify a certificate by hash, check a student result, raise an issue — no login, no PII exposed) and an admin portal (dashboard, certificates, results, analytics, issues, activity log, user management, branding and downloads). It is built on a Node.js + Express REST API with a PostgreSQL database and a React front end. Certificate hashes are optionally anchored on the Sepolia testnet blockchain for permanent, public proof.

2 · Key Features

🛡️ Tamper-Proof CertificatesSHA-256 hash per certificate; optional IPFS + Sepolia on-chain anchoring.
⚡ Instant Public VerificationVerify by hash only; validity status returned, never personal data.
🔐 Role & Department Scoping7 roles with per-user section permissions and department-level API enforcement (403).

6 · Policies

🤝 Privacy Policy

  • Public verification only. A hash returns only "valid" / "not found" — names, roll numbers, results and contact details are never exposed publicly.
  • No unnecessary collection. Only data required to operate the portal is stored (name, roll number, course, department, year, email, marks/grades, optional mobile/Aadhaar for exports).
  • Under your control. Results are visible only to administration and staff granted access; department restrictions further limit visibility.
  • Share the certificate, not the record. Holders share the hash so employers verify authenticity without revealing private records.

🛡️ Security & Data Protection

  • Strong password storage: scrypt hashing; legacy SHA-256 hashes upgraded automatically at login.
  • Session-based auth: random 64-char tokens in PostgreSQL; 12-hour idle expiry.
  • Rate limiting & lockout on repeated failed logins per IP.
  • Server-side authorization on every protected endpoint (session + role + permission + department).
  • ROPA & DPIA: apps complete a GDPR Art. 30 register and Art. 35 risk assessment before going live / before high-risk processing; the admin portal tracks compliance per application.

7 · Support & How to Raise an Issue

Students can raise an issue directly through the portal (roll number + semester); the records office triages it as open / resolved / rejected. Administrative and technical support is handled by the University Official Records Office.
